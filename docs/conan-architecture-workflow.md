# 柯南建筑与街区还原方法

更新：2026-09-12。此文记录本轮 Blender 建模与几何验收；实际游戏行走、网页与移动端发布状态，以对应运行报告为准。

## 参考、原工程与采用关系

用户指定的[米花建筑资料](https://felicia1012.pixnet.net/blog/posts/14219272223)用于核对毛利楼层用途、伊吕波紧邻关系、工藤与阿笠邻居关系，以及阿笠圆弧住宅、屋顶太阳能板、后车库。它属于资料整理，不是测绘文件。本轮宽度、层高、进深和街道距离是按游戏行走净空推定的制作尺度，不宣称官方比例。

用户图 1/2 的用途是毛利楼与连续商铺的关系，夜景蓝色不直接作为日间墙色；原毛利三层可探索建筑保留，1F 波洛、2F 事务所、3F 住宅。新增街区把伊吕波寿司紧贴在毛利右侧，并补连续的 3–5 层商铺、屋顶设备、女儿墙、窗框、卷帘与人行道。普通商铺属于街区场景，不宣称每间都有完成的游戏任务或开放室内。

用户图 3/6/9–12 分别控制阿笠的外轮廓、室内位置和家具细节：双层圆弧翼、中央入口、后圆塔、太阳能板；环形厨房左邻并列双床、右邻客厅、上方环廊；后塔连续上下楼梯；地下研究室和发明工作区；后车库与真实室内步行连接。图 7/8 只用于地标相邻关系，不能拿插图地图推导精确街道尺度。

原项目中可复用的毛利建筑和阿笠仪器均为 Blender 源文件。人物与博士甲壳虫仍用独立 Tripo 资产，普通车的朝向、轮轴与行驶逻辑没有被本轮建筑脚本更改。仪器已抽成独立的 `agasa-lab-source.blend`，新建筑不依赖旧工作目录的绝对路径。

## 文件与重建顺序

脚本在 `tools/conan/`；新模型源与本地原始备份在 `worlds/conan/blender/reference-2026-09/`。大体积源文件和运行资产按项目资产发布方式归档，不应误提交临时 `.godot`、`.blend1` 或 Python 缓存。

1. `build-agasa-reference.py -- --grey --render`：真实同模型灰模多视角，不把概念图当几何依据。
2. `build-reference-block.py -- --grey --render`：连续商铺与原毛利楼同场景核对，输出的新 GLB 不重复包含原毛利楼。
3. 去掉 `--grey` 生成材质、仪器、样本架、灯具、木框等真实模型细节。阿笠制作源为 `agasa-reference.blend`，街区源为 `street-block.blend`。
4. `patch-street-context.py` 用原始备份执行有范围的旧场景修补；反复执行从同一备份开始，不叠加切孔或重复删除。
5. `prepare-reference-runtime.py` 复制原版至 `source/assets/buildings`，生成 `web-project/assets/buildings` 衍生。只缩小图像和非碰撞小细节，不减少 `_Collision` 网格。
6. `verify-reference-geometry.py` 检查源/网页碰撞三角、原图像字节、旧楼残留和孔内外射线。必须再跑 `tools/test-conan-reference-routes.gd` 的真实角色移动，几何一致不能替代可走性。
7. `build-reference-study.py` 将实际街区与毛利、工藤、阿笠等模型放在同一 Blender 场景，检查邻居关系和遮挡。该图板仍属于 Blender 模型证据，不是引擎或网页截图。

Blender 5.2.1 从空工厂场景创建时 `scene.world` 可能为空，先创建 World 再设置灯光节点。后台启动在本机沙箱内曾立即崩溃；获准本地模型渲染后使用正常 Blender 进程执行，不把启动崩溃误判为生成脚本几何错误。大量零件用数据 API 创建，避免每个小盒子都触发操作器与依赖图刷新。

## 引擎合同

所有建筑 GLB/JSON 使用 Godot Y-up 米制局部坐标。阿笠 `origin=[64,0,-7]`、`yaw=0`，毛利新增连排街区复用原楼 `origin=[7.8,0,-3.4]`、`yaw=PI/2`。可碰撞节点带 `_Collision` 后缀；补充简单碰撞在 `colliders[{p,s,r,rx}]`。

阿笠 `floor_levels` 是地下 `-3.12`、主层 `.06`、环廊 `3.18`；后塔 `stair_hole` 中心局部 `[0,0,-5.9]`、全局 `[64,0,-12.9]`、半径 `2.18`。楼梯由连续螺旋碰撞坡面和独立可见踏步构成，不能只放视觉台阶。`routes[{name,points,expected_y}]`、`rooms[{name,p}]`、`views[{name,p,target}]` 使用相同局部坐标。

`lights` 给每个房间有范围的低能量 Omni 填光，含 `p/energy/range/color/shadow/attenuation`。这些补光默认无阴影，窗口另承担方向性照明。`windows` 提供真实窗孔位置和朝内法线；`interior_zones` 提供包围区域。不能靠移除整面墙或全局加曝光修室内黑。新增材质用 `Agasa reference` / `BeikaRow` 前缀，避免引擎按旧同名材料误覆盖颜色。

甲壳虫停在车库局部 `[11.5,.065,-4.85]`，沿车库纵深摆正；行走目标在车旁 `[10.1,.06,-5.8]`。把车中心当路线终点会造成角色撞车，不能把这种失败归因于寻路。

## 本轮实际发现的坑

### 地下室并非降低一层地板即可

旧街区的 `Terrain_Collision` 是横跨整片城市的地面，住宅独立 GLB 即使有楼梯，角色仍会被原地面封住。这里只对后塔圆孔分割原三角面，不删除整片阿笠地块；大范围删除会让院子失去地面。备份、原 SHA、去除节点/材质/面数及范围在 `*-street-patch-report.json`。

补丁只去掉原独立伊吕波楼及其屋顶、帘子和旧名牌；保留学校、车站、公园等没有替换的地标。旧屋顶高度高于主墙，筛选范围若只到墙高，会留下浮空屋脊。修补后核对完整旧楼包围范围内的剩余三角为零。原嵌入纹理按内容 SHA 核对，普通车资产未触碰。

### 楼梯孔和桥端需要真实交叠

首轮真实行走通过了入口、厨房前和入塔，但由圆塔回大厅时卡在孔边。原因是孔前沿在 `z=-3.72`，桥前端只有 `-3.98`，留下 26cm 缝；角色脚先落低，再撞楼板侧面。第一次把桥延长虽补了缝，实际向上走又发现平台盖住了螺旋最后转角的头部净空。左侧切向桥尝试又横穿了同圈刚开始上升的坡段，这个尝试撤销。最终把每圈起末各 30° 做同高平段，剩余 300° 连续爬升；正前径向桥落在完整 60° 平台内，连角色胶囊宽度一起检查，后环廊仍挖半径 2.4m 净空。平台并非只检查脚落点；还必须把角色高度和胶囊半径叠上去检查侧面、底面。上下行与整圈环廊重新跑真角色验收，不能用增加容差或自动抬升穿过平台。

### 地形底面会挡住室内顶棚

实机地下室抬头看到草地，不是颜色贴错：旧地形是有厚度的实体，底面约 `y=-.43`，原室内顶棚在 `-.20`，反而埋在地形里面。增加位于 `-.56` 的真正不透明室内吊顶（净高 2.56m），同步降低顶灯与通风口，并给楼梯保持 2.4m 圆孔净空。不能只从屋外看顶板存在就判断室内封闭。

### 有仪器不等于仪器位置正确

旧实验台复用时若只下降到地下，不核对新平面，会横跨研究室新门洞。仪器与台面整体移到发明工作区左墙侧，随后用独立安全碰撞覆盖桌体。新电脑必须把屏幕和键盘朝向操作者，而不是朝墙。室内全景与近景都要从实际房间内取景；不得通过隐藏建筑墙体把局部陈列说成可探索空间。

### 抽样射线与真实身体解决不同问题

孔内 60 条垂直射线无阻挡、孔外 12 条射线有地面，只说明圆孔存在；源/网页三角一致只说明衍生过程没改碰撞。它们都无法发现桥端小缝、桌椅路线或转弯时身体擦墙，因此必须有真实 CharacterBody、完整回程与门洞转向测试。

最终几何冻结后，环廊路线的规则椭圆采样仍穿过了两根前侧结构柱。只增加左右对称的外侧绕柱点，保留柱体和碰撞，不把合理障碍删掉以使测试通过。最终 [pass06](evidence/conan-architecture/route-pass-06/physical-routes.json) 完成 41 组检查、291 段真实行走，零失败，包含地下双向、完整环廊双向、车库往返与返回门外。报告绑定具体运行资产及控制器 SHA；后续若改变碰撞或控制器，需重新验收受影响路线。

### 统一源坐标与引擎旋转

本轮 Godot 到 Blender 的位置映射为 `(x,y,z) → (x,-z,y)`，Godot 正 Y 轴旋转对应 Blender 正 Z 轴旋转。共享街区渲染曾因额外取负把毛利楼朝向反转，局部书架与护栏也因此不沿真实切线。用实际引擎朝向核对后纠正共同坐标函数；不要通过在每个对象上追加补偿角度掩盖全局约定错误。
