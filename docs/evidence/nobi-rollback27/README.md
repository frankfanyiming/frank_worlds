# 第 27 版：精简首页，只恢复大雄家

用户明确要求移除留言板、移除整块头图，并授权将线上大雄家恢复为提供截图对应的旧版。首页直接展示三个原封面，作者联系方式、制作手记、Skills、共创入口和非商业/IP 说明保留。留言板入口、表单与故障提示从首页移除；没有删除或迁移后端历史数据。

## 恢复范围与缓存边界

- 来源为 `bafe7f3fa6f9aa63a9e02a3729c77432335ef885` 的 v10 资产。仅取 `home_*`、`facade_*`、一楼家具、二楼西房家具、房屋窗户、生活小物与楼梯细节。
- 当前 `bedroom-v12` 已保留旧卧室的详细模型与修复过的门口，继续使用。未重复叠加旧 `hero_*`、书桌物件或院子资源。
- 当前 `neighborhood-v21` 原文件不动，只在装配时卸下 `v11_home_*` 层。静香、胖虎、小夫家仍使用相同模型、材质、坐标和碰撞数据；其它两个世界未改。
- 新房屋使用独立文件名 `nobi-home-v27.glb`。碰撞数据也单独命名 `world-v27.json`，旧页面继续请求旧 `world.json`，避免缓存中的旧外观配到新碰撞。
- 手机版独立为 `mobile-v27/nobi-home-v27.glb`，继续使用现有帧率目标、自适应像素、触控、按需二楼加载及取消/重试逻辑。桌面其它资源与缓存版本不变。

## 发现的问题与修正

原 v10 元数据的楼梯位置已经过时，不能直接照抄。对实际模型的 16 级踏步逐级测量，确认中心为 X=-13.05、运行坡道 Y=1.2–4.8、层高 0.48/3.15。

旧楼梯两侧的连续侧板与扶手封住了入口到客厅的通道。直接换回旧碰撞后，路线检查失败。局部修剪楼梯下端 55 cm 的侧栏并封住切口，保留 16 级踏步，碰撞边界同步修改。最终真实控制器可连续上、下楼，两份解码模型的 18 条通道射线均无障碍。

首次手机版简化仍有约 78 万面，原因是原资源大量 UV/法线接缝限制了折叠。采用带法线和 UV 误差权重的网格简化，仅修改手机版；控制位置误差并保留节点与变换，最终约 24 万面、3.56 MB。桌面约 150 万面、22.10 MB。两种资源的外观和厨房均在 Blender 预览核对。

## 已验证

- `assets.json`：6 个 Git 原始文件指纹、选取节点、局部修剪、PC/手机结果与节点变换。
- `scope.json`：三封面、邻居房屋、现有卧室、基础街区和旧地图字节不变；其它碰撞、地形与角色位置不变。
- `desktop-geometry.json`、`mobile-geometry.json`：16 级实际踏步、5 个一楼地面探针通过。
- `clearance.json`：在实际解码模型上验证入口到客厅的通行空间，无 WebGL 或浏览器。
- 运行测试：两座楼梯、7 条室内路线、真实控制器连续上/下楼；延迟二楼、取消/重试、缓存；手机输入及动态分辨率；首页静态与运行时故障兜底。
- TypeScript、Sites 正式构建、Pages 构建通过。首页入口仍不静态加载 Three.js 或世界引擎，资源审计见 `bundle-audit.json`。
- PNG 是 Blender 模型预览，不是网页截图。本轮没有浏览器视觉测试或实体手机帧率测试。
