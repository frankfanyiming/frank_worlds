# 3D 世界制作方法与复盘

更新：2026-09-12。来自小世界项目的实际迭代，按用户要求持续积累。
每条经验需要说明问题、证据、修正及适用范围。不是给所有项目增加统一审批步骤。

## 2026-09-12：几何能走通，不代表还原了参考

用户在两户住宅首次实机检查后指出：地板、墙面细节少，像水泥罐子，缺乏呼吸感；角色腿部动作不明显，像平移。这次反馈推翻了“主要家具齐全即可进入发布收尾”的判断。两户装修归属与适中比例继续保留，细节与动作重新制作。

直接证据：第二次实机近景中，地面是大小接近的多边格，墙面大面积单一灰色；树桩年轮是规则圆线，木纹呈粗条带，储物罐外形重复，布面缺少织纹与厚度。参考要求的是有大小变化、碎边和颗粒的石板，大块连续岩层的浅起伏，树皮裂缝、手工陶釉、编织与生活物件层次。只提高面数或再叠一层噪声并不等于还原这些特征。

后续按三个尺度验收材质：轮廓和大结构、厘米级裂缝/碎边/木节、毫米级矿物颗粒/纤维。轮廓必须由实际几何承担，细表面使用可随 GLB 导出的颜色、法线和粗糙度；不能只在 Blender 的程序节点预览中存在。网页使用的 Compatibility 渲染也要检查，不能把不可用的屏幕空间效果作为关键细节来源。

镜头也必须单独验收。把高处俯看作为可切换总览，日常采用较低的近距离视角；相机需要同时尊重围护与家具遮挡，不能通过隐藏整堵墙来获得构图。以玩家实际镜头检查腿部、桌面与石材，而不是只有摆拍大图。

旧蛙步态的量测发现：28 帧/30fps 的周期，支撑脚后移约 .146m，匹配速度约 .313m/s，而运行时以 2.9m/s 前进，约九倍差距。新动作必须给出周期、支撑阶段、实际脚掌位移和基准速度，再用角色碰撞后真实位移驱动播放速率。撞墙时不能继续走路；起跳蓄力不能在同一帧被 JumpAir 覆盖。验收需要真实走步视频、足底采样和起跳/空中/落地序列，不能仅检查动画名字存在。

细化与颜色实验的复现记录见 [住宅制作方法](household-production-method.md)，角色的权重、重合顶点接缝与步幅验收见 [角色动作复现流程](character-motion-workflow.md)。本节记录已发现的问题与本轮处理标准，发布状态以最终实机报告和 release.json 为准。

## 2026-09-11：调整比例时锁定原有装修

2026-09-11 用户指出：青蛙家应继续使用原图的装修；上一轮连续岩壁、贴墙直梯、矩形茶桌的样式可以给熊猫或松鼠家，而且蛙已经缩得太小、房间放得太大。

这说明上一轮有两个失误：把“空间稍宽敞”扩展成整套装修替换；又把“比例再小一些”持续向极端推进。不能把助手自己的图像评价写成用户已接受的结论。

后续方法：
- 先列出用户要保留的识别元素。青蛙家包括树干、蘑菇台阶、睡铺、小圆桌、叶子与原作生活物件。先修它们的直径、摆位和遮挡，不直接删除整套布局。
- 尺度先用中间档小幅试调，并与原实机、上一版过度调整并排对照。本轮采用房宽 11.2、蛙高 F=1.08，即约 10.37F；15F 与 45% 空地不再作为青蛙家的采用参数。
- 用户把某种风格分配给其他角色时，分别建立角色住宅档案。旧石屋方向本轮先分给熊猫，加入克制中式竹木、茶具、圆窗花格。
- 原作装修、材质参考、比例参考、新角色住宅参考各自标注用途。主参考顺序不要因辅助图更清晰或更好看而被替换。
- 两个方案同时出现时，每张图都写明是哪位住客的家。概念图记录设计取舍；获准方案已制作成独立 Blender 资产并接入 Godot，不能再把整个工作标为“仅概念”。

历史设计取舍见 [第二轮空间提案](design/frog-spatial-study/revision-02/README.md)；当前细化模型见 [蛙家四视角](evidence/frog-home/detail-pass/README.md) 和 [熊猫茶屋细节](evidence/panda-home/details-02/README.md)。实机视觉与行为证据见 [两户实机验收](evidence/households-runtime/README.md)；在线版本由发布清单另行核对。

## 先确认问题处于哪一层

旅行蛙先后修过穿透房屋、石材颜色和墙面纹理，但用户仍然觉得室内拥挤。比例研究前的实机中，中央树干与螺旋楼梯占据主要画面，角色和桌子靠近广角镜头；墙面正确并没有解决空间比例。

以后按顺序拆解：
1. 空间：角色、房间、家具的比例与可通行区域。
2. 布局：门、床、桌子、楼梯、活动区的关系。
3. 镜头：实际位置、遮挡、透视与可视范围。
4. 材质、灯光、装饰。

不要用第四层的细化掩盖第一层的问题。当用户明确要求“先出图看看”时，先完成概念和尺度说明；本轮方案获准后已进入模型与引擎实现，不再停留在等待概念确认的阶段。

## 以角色为尺，先做灰模

用角色站立高度 F 统一度量房宽、层高、门高、台面、台阶和通道。区分模型高度、碰撞体高度和相机高度，不能混用。

先记录基线，再记录实际采用值。比例研究前的室内半径为 4.72、宽约 8.7F；宽 15F、深 12F、夹层 3.8F 的第一轮提案被用户指出过大，已撤回为历史探索。当前蛙家 Blender 模型保留蛙高 F=1.08，房宽 11.2、深 9.8、顶高 6.6、夹层标高 3.25；这些来自真实模型和布局元数据，不是从 AI 图片测出的尺寸。

房间放大、角色缩小和家具缩小要统一换算，避免每项都独立乘系数造成叠加失控。至少保留一圈能够让角色和访客通过的动线。台面和座面也必须适配角色，不能只靠大房子把角色衬成宠物。

进入建模阶段时先做低细节 Blender 灰模，以真实游戏相机渲染入口、侧面、夹层反打；再运行角色走路、转向、跳跃和上下楼。灰模确认了空间，再增加高成本纹理、装饰和细节。

## 多视角需要共用布局

固定门窗、床、楼梯、桌子的位置和命名，再生成其他视角。先选一张比例合适的主图作为后续图的参考，比各角度从文字独立生成稳定。

上一轮主图随后把角色缩到初稿的 65%、茶桌组缩到 70%，建筑体量和镜头保持一致。助手当时认为更合适，但用户明确反馈蛙过小、屋子过大。因此这个缩放结果不能作为成功经验；它只说明定向编辑能够改变比例，审美是否合适仍要依据用户反馈。

AI 多视角仍可能改动栏杆、门窗、家具朝向和数量。它适合定气氛与比例，不能作为一致的施工几何或替代 Blender 的同模型多机位渲染。要公开标明“概念图”，不要称为实机或已实现功能。

## 材质要拆成形状与表面

“石头屋”有至少两种不同表达：连续天然岩壁，或一块块砌筑石砖。用户参考明确偏向前者：宽大不规则岩面、少量裂隙、灰米色矿物；地面才是不规则石板。

先逐项记录墙、地、木构、布料和光线。不要只根据“石头”关键词替换成规则砖缝，也不要把内壁做成树皮。

程序色彩贴图要检查线性与 sRGB 的转换；法线等数据贴图使用 Non-Color。本轮独立色块实验确认：Blender 5.2.1 的 8-bit sRGB 生成图片经 pixels 写入、pack 和 GLB 导出时，线性 0.25 需先编码为 sRGB 0.537099；直接写 0.25 的图像明显更暗。适用条件和结果见 [颜色校准证据](evidence/material-calibration/README.md)，不能扩展成所有图片 API 的通用规则。最终颜色仍以 Godot 实机为准。

## 密闭室内与庭院分开处理

此前把整个房屋外壳按靠近距离隐藏，形成了能看见庭院的剖面。用户希望进家后看到密闭空间。

当前实现使用独立室内围护、真实墙顶与碰撞；穿过门槛进入室内后停止显示庭院，进出阈值留滞回区间。门口、墙角、夹层与蛙眼视角都要验证。编辑器剖面或鸟瞰设计图不能直接等同于玩家镜头。

固定构图的二维室内插画不能直接套入自由旋转的广角相机。先放置相机，再检查遮挡；中央树干、楼梯等大件必须从每个正式镜头都可接受。焦距和游戏的垂直 FOV 不是同一个数值，应明确相机参数与宽高比。

## 阴影修正应有明确范围

室内聚光在向内岩面上出现平行自阴影条纹。当前围护关闭自身投射阴影，保留家具投影和围护碰撞，改善了此特定封闭房间的效果。

这不是所有物体都关闭阴影的理由。以后先查法线、光源位置、偏移、薄面和贴图，再选择范围最小的修正，并在昼夜切换中检查。

## 保留可编辑源，再优化运行资产

Blender 原生文件保留分物体、材料、可编辑构件与贴图。导出运行副本时才按材料合并，避免为了减少绘制批次丢失源文件结构。

本轮蛙家围护运行 GLB 为 11 个网格，家具为 23 个。可编辑源在 `worlds/frog/blender/frog-home-enclosure.blend`、`frog-home-furnishings.blend`；同目录 `frog-home-review.blend` 用于同模型四视角审查，熊猫住宅源为 `panda-home.blend`。优化还必须检查：透明窗面、碰撞名称、门轴、角色骨骼、贴图方向。角色模型与场景分别记录来源，Tripo 生成加 Blender 绑骨不能写成“全部由 Blender 建模”。

对新伙伴先检查三视图的物种、轮廓、花纹、四肢分离和配件，再生成模型。尾巴、背包、领巾保持可拆与可修正；不要让手持道具遮住待绑定的手臂。AI 参考图不是已完成的 Tripo 模型。

## 验证真实路线与真实画面

改动地板、碰撞、楼梯和角色尺寸时，从真实出生点走到门口再进屋。曾经把角色直接放进转动中的门碰撞，得到错误的验收失败。

当前两户验收入口为 `tools/test-frog-households.gd`，从真实出生点覆盖进出两户、上下楼、跳跃、墙体与相机；`tools/test-frog-home.gd` 是旧蛙家检查脚本。布局重做后要同步路线参数，不能只重复旧路线并宣称新布局可用。截图至少留：进门、室内主视角、夹层、第一人称、昼夜、出门。

可逆文档与概念图迭代只需检查文件、图片和展示页面；无需运行整套游戏测试。实现变化再运行对应检查。

## 网页加载与发布

大型世界需要流式下载进度、超时、重试、断点恢复、文件完整性校验和明确失败反馈。大包下载问题与共创服务端 403 要分开定位。

运行包分块发布后检查实际在线清单、分块与校验和。不要把本地构建成功当作线上可用。

异步提交命令可能尚未结束，必须确认提交成功后再推送，避免上传旧 HEAD。普通网络/SSL 中断先以同一提交重试，不要使用强推来解决网络问题。确认远端提交、Pages 构建状态与公开 release.json 的 sourceCommit 一致后再报告已上线。

源代码、运行包、完整原始模型归档是不同发布对象。归档当前标记为 pending-publication 的，不能因为发布了代码就声称完整模型已经公开。

### 2026-09-12：室内真实柔光与 Web 兼容烘焙

两户住宅实测的 LightmapGI 接入、Metal 烘焙 / Compatibility 显示、HDR 数组贴图压缩、跨项目 UID、UV2 三角变化和静态/动态灯分工，见 [两户住宅柔光烘焙方法](house-lighting-method.md)。此记录基于实际引擎前后图；不要把 12 倍烘焙能量校准或“有用户数即成功”当成通用规则，也不要将角色纳入静态烘焙。

### 2026-09-12：脚步必须以地面位移与侧面姿态验收

旧蛙模型有骨骼和 Walk 片段，但脚向后的速度约 0.31 m/s，角色移动却是 2.9 m/s，造成明显平移感。修复要同时处理脚掌支撑、左右抬脚、身体重心与实际移动速度；遇墙停止后也应停止迈步。当前脚步速度合同在 `assets/locomotion.json`，运行时使用碰撞后的真实速度驱动动画。熊猫用 CharacterBody3D 沿茶桌附近的路径走动，而不是逐帧改位置。测量值、脚底漂移与真实录屏见 [角色动作方法](character-motion-workflow.md) 和 [实机证据](evidence/households-runtime/README.md)。

蒙皮接缝零撕裂不代表四肢不互相穿透。蛙 JumpAir 初版脚趾卷进大腿，前视不明显，侧面实机很清楚。最终仅修改空中腿部姿态，减少上收并向前伸脚，保留其他动画、网格、UV 和材质；之后重新录制侧面完整跳跃。

角色身上的圆环经过 GI、法线贴图、投影的独立 A/B 验证，实际来自室内 Spot 阴影。为两户窗灯设置 `shadow_reverse_cull_face=true`，保留阴影开关及原偏移，圆环消失且静态房间像素未变。不要看到圆环就重做模型或提高环境光；本修复仅对已经验证过的灯光/角色组合适用，见 [阴影排查](evidence/character-motion/spot-shadow-audit/README.md)。
