# 小世界共创

用户先逛世界，再从某个世界开分支。首版以“新增地块和改造拓展区”为共创范围，核心故事场景继续由维护者维护。这样用户可以做出能玩、能分享的作品，也能逐步扩大同一个主世界。

## 页面与参与路径

- 首页三个主世界入口使用指定标题；自然语言创建完整世界的输入框暂时置灰。
- “大家的小世界”展示真实发布的分支，可按所属世界筛选，区分公开作品与自己的草稿。
- 访客打开分支可参观，也可以复制一份改造。作者在 3D 编辑器添加地块，摆放、移动、旋转和着色 Blender 物件。
- 来访本直接显示输入框：留言最多 500 字、昵称、所属世界，以及选填的联系邮箱。邮箱单独保存，仅维护者可见，删除留言时一并删除。
- 主世界内以及网页顶部均有“共创拓展区”入口。通过审核的地块在同一张地图中相邻连接，所有访客可进入。

## 冲突和合并

每个分支保存创建时的主世界快照。合并时对比基准、当前主世界和提案快照。发布、提案、主世界修订均固定到具体版本，作者后续修改草稿不会偷偷改变已经公开或正在审核的内容。

| 情况 | 处理 |
| --- | --- |
| 不同物件、不同字段各自修改 | 自动合并 |
| 同一字段双方都改成不同值 | 明确选择保留主世界或采用分支 |
| 一方删除、另一方修改 | 明确处理删除与修改冲突 |
| 不同分支占用同一地块坐标，或物件相交 | 退回分支调整位置，再发布新版本与提案 |
| 审核过程中主世界又更新 | 拒绝旧版本写入，重新计算差异 |
| 发布后发现问题 | 回退为一个新修订，保留历史和原分支 |

只有经过身份验证的维护者可以把提案合入主世界。公开用户不能直接写主世界。每个世界最多 64 块地，每块最多 20 件物品，地块必须相邻；大物件不能堵住交叉小路。

访客草稿通过浏览器持有的随机凭证认领；原始凭证只在设备本地保存，服务端保存其摘要。更换设备或清空浏览器会失去该访客草稿的编辑身份。下一阶段可接入可恢复的用户账户，再开放私有协作邀请与角色权限。

## Agent

自带 Key：当前支持用户的 OpenAI API Key，可填写有权限使用的模型。Key 只在当前页面内存中，请求直接发送到 OpenAI，不进入站方数据库、作品或 Git。

平台 Agent：默认 `gpt-6-astra`。采用付费账户余额，先预留请求预算，成功后按实际 token 结算，失败或无法应用的方案退款。支付确认以验签后的服务端支付通知为准，不能靠前端“支付成功”页面增发余额。相同支付与相同 Agent 请求均使用唯一 ID 防重。

Agent 返回经过结构校验的物件操作，只有应用到草稿后才改变个人分支；不会执行生成的脚本，也不能直接发布或自动合入主世界。当前平台付费服务默认关闭，等账号、密钥、价格和收款配置完成后启用。

## 后续扩展顺序

1. 补全可恢复账号、收藏与作者主页，让用户能跨设备继续自己的作品。
2. 给主世界维护者提供地块认领与预约，减少多人同时建设同一区域造成的位置冲突。
3. 开放模板化建筑和任务组件；仍使用稳定 ID 与结构化差异，不直接合并二进制模型文件。
4. 在沙盒中生成自定义 Blender 物件，经过面数、尺寸、碰撞与性能检查，再进入候选资产库。

首版不依赖实时多人编辑。未来同一分支多人在线操作时再增加短时编辑锁与操作日志；最终主世界发布仍保留提案、版本条件与回退机制。
