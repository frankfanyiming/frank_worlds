# 住宅场景制作方法：旅行蛙第二轮

2026-09-12。本文记录本轮建模、Blender 审查渲染与独立颜色实验。**不代表 Godot 全程验收或网页已发布。** 游戏运行与发布状态见主任务的独立记录。

## 先锁定装修，再调整比例

本轮走过的弯路是把“空间稍大一些”理解成更换整套装修，又同时放大房间、缩小蛙和家具，累积成空旷大厅。用户明确要求恢复原作装修，把另一套石屋交给熊猫。

后续先列出每户的识别元素和参考图用途。蛙家锁定左侧树干、蘑菇台阶、后夹层蓝色睡铺、圆木桌、叶子布艺、陶罐架与双灶；较清晰的辅助图只补充材质或细节，不覆盖主要布局。熊猫家的竹木茶室另建资产和场景，避免两户混用装修。

用角色身高 F 作统一尺度。本轮蛙保持 F=1.08 个世界单位，房宽 11.2（约 10.37F）、深 9.8（约 9.07F）、顶高 6.6；夹层标高 3.25。房间尺寸、角色碰撞体、家具使用高度和可行走通道一起校核，不能对房间、角色、家具分别盲目乘缩放系数。画面中蛙的占比还受相机距离与俯角影响，不能从一张图片直接推定物理尺寸。

这些数字适用于本轮蛙家，不是其他动物住宅的统一规格。闭合围护与主、入口、夹层相机使用同一模型；AI 概念图只提供设计意图。

初次建模证据：[同模型三视角及来源](evidence/frog-home/README.md)；细化后证据：[当前四视角](evidence/frog-home/detail-pass/README.md)。

## 楼梯必须在正确标高接上平台

楼梯围绕左侧细树干布置：树干中心为 Blender 局部 `(-3.55, 0.45)`，路线半径 1.04；21 级台阶从地面 0.188 升到夹层 3.25。原先设计的 540° 圈梯在末几级还未达到平台标高时，就进入了夹层前沿，存在几何交叉。

修正为 510° 后，末阶落在夹层前沿且达到 3.25：Godot 坐标约 `(-18.03, 3.25, -13.35067)`，再接到平台内 `(-18.03, 3.25, -14.02)`。同角度的上下圈台面高差约 2.06，扣除台阶厚度后再与角色高度比较。不要只检查单级高差而忽略上方台阶或夹层的净空。

可见蘑菇台阶与可行走碰撞分工：模型保留台面；运行时依据同一份路线生成宽 0.90 的连续坡带，避免 CharacterBody 被竖直小台阶卡住。不要再叠加台阶盒碰撞。夹层用真实轮廓多边形，左侧入口保持可通行。最终上下楼仍须由游戏真实控制器检验，不能把静态路线连通当作已经走通过。

坐标契约也应写入资产元数据：本轮 Blender 中心 `(-15,12,0)` 对应 Godot `(-15,0,-12)`。楼梯、家具碰撞、平台轮廓、相机与交互点从同一布局导出，避免重复手填后逐渐错位。

## 实渲中遇到的四个几何问题

| 问题与证据 | 有效修正 | 适用范围 |
|---|---|---|
| 第一张渲染地面纯灰，石板消失；底衬顶部比石板高约 0.001 | 降低底衬，保留石板顶面 0.188；复渲可见石板及接缝 | 重叠地面层先核对实际标高，再怀疑材质。碰撞面可以略低，但必须记录差值 |
| 蓝被上出现大片白色；床垫穿过被面的波谷 | 降低床垫并减小厚度；复渲被面连续 | 软装建模要比较褶皱最低点与底层最高点，换纹理不能修穿模 |
| 地图出现黑裂片；多块平面墨迹在同一平面交叠 | 每块墨迹沿墙法向错开 0.003，线条置于最前 | 共面贴花/装饰；不能据此给所有对象随意加偏移 |
| 左侧夹层出现黑片；落地板与原平台重复覆盖 | 删除多余落地板，用原平台接楼梯 | 同一表面优先消除重复几何，不靠照明掩盖 |

[初次建模的三张修正后 Blender 图](evidence/frog-home/README.md)均已实看；这组图只能证明所展示构图中的可见结果，不能替代碰撞、动态镜头或不同时间照明的实机证据。

## 颜色太亮时先做标准色块实验

曾怀疑 `Image.pixels` 写入前转 sRGB 造成“双重提亮”。独立实验否定了这个判断：在 Blender 5.2.1、`float_buffer=False`、sRGB 生成图片、`pixels` 写入后 `pack` 并导出 GLB 的流程中，**线性颜色要先编码为 sRGB，再写入 8-bit 图片缓冲，才能与常量线性材质一致。**

三块等尺寸、同法线平面使用同一均匀白色 World 光；Cycles 64 samples，Standard 变换，无 Look 或曝光偏移。中央 48×48 像素实测：

| 材质 | 原场景平均灰度 | GLB 回导平均灰度 |
|---|---:|---:|
| 常量线性灰 0.25 | 136.966 | 136.966 |
| sRGB 图片直接写 0.25 | 64.007 | 64.007 |
| 线性 0.25 编码为 sRGB 0.537099 后写入 | 136.988 | 136.988 |

Emission 材质排除灯光后得到相同结果。GLB 内嵌 PNG 中，直接写入组为 64/255，预编码组为 137/255；前者经 sRGB 解码后只有约 0.0513 线性亮度。删除预编码能让纹理变暗，但它降低了实际反射率；若裂隙、灰缝仍用常量线性色值，材质之间会失去统一标准。

实际调色方法：先明确参数是线性反射率还是显示用 sRGB 色值。线性参数直接用于常量节点，编码后用于 8-bit sRGB 图片；显示用 sRGB 色值则先解码用于常量节点，原码值用于图片。亮度问题在真实反射率、光照与曝光中解决。

本实验没有测 `float_buffer=True`、线性图片空间、Non-Color 法线贴图或其他图片 API，不能外推为所有图像写入方式的规则。完整图、数值、GLB 和可复现脚本见 [颜色校准证据](evidence/material-calibration/README.md)。

## 交付时保留四种状态

- Blender：可编辑模型、布局契约、同模型多视角和材质证据。
- Godot：真实角色移动、跳跃、上下楼、墙体、动态相机与照明。
- 网页：发布清单、下载与加载、实际在线版本。

本页主要记录第二种状态；模型已经接入 Godot，但本页不作最新视觉验收或发布结论。可编辑源位于 `worlds/frog/blender/frog-home-enclosure.blend`、`frog-home-furnishings.blend`，同目录 `frog-home-review.blend` 保存四个审查视角；熊猫住宅源为 `panda-home.blend`。原生 Blender 保留分物体，运行 GLB 再按材质合并；角色来源仍是 Tripo，不能因在 Blender 调骨骼或摆审查姿态就改写来源。一次渲染好看、一次导出成功，都不能代替后两种状态的验证。

## 细节返工：从规则灰面恢复材料与生活感

用户在第二轮实机中指出石壁、地板像水泥罐子。对照最新近景参考，问题不只是颜色：原围护大面平滑、地面种子排列近似规则网格，树皮和罐子依赖简单周期纹理；远景能认出房间，近景却缺少材质尺度与手工差异。

本次保留房宽、蛙高、家具主要位置、510° 楼梯路线和夹层碰撞契约，只重做可见几何和能进入 GLB 的贴图。最新证据见 [同模型四视角细化审查](evidence/frog-home/detail-pass/README.md)；该目录是 Blender 渲染，不是 Godot 截图。

| 问题 | 实际修正 | 检查边界 |
|---|---|---|
| 岩壁只有均匀灰面 | 将墙展开为角度×高度，随机间距种子切出大小不一的宽岩面；边缘贴连续基底，内圈形成约 0.05–0.15 的浅浮雕斜面；并入原墙碰撞网格 | 保留闭合基底；不能把视觉岩片当作无碰撞贴花。入口区域不增岩片，路线数值不变 |
| 地面接近规则六边形 | 改为混合间距散点，较长边加入浅碎缺；石板真实倒角、窄而温和的灰缝；三种接近的米灰材料 | 不用黑色粗线假装缝隙；石板顶高保持 0.188 |
| 木纹、陶釉出现明显周期波纹 | 树干细分为真实纵向浅槽与小眼节；纹理叠加不同尺度的非规则变化；陶釉改为不规则深浅斑，只留很浅的拉坯痕 | 多层正弦叠加仍可能显得机械，需要实际近景检查，不能仅凭节点复杂度判断 |
| 桌凳年轮像粘上去的电线 | 删除抬高圆环几何，顶面使用归一化圆面 UV 的细年轮颜色与微法线；只保留少量很细的干裂 | 圆柱默认 UV 不能保证年轮中心与木面中心重合，要检查导出前真正 UV |
| 叶毯缝线被厚度埋住、边缘像珠链 | 修正叶片面朝向，厚度朝下；叶脉贴着曲面；边缘绒簇改变角度、大小和密度 | 可见厚度、线条与表面最低/最高点一起比较；单纯加绒簇数量不够 |
| 器物整齐复制，灶口像画上去 | 陶罐区分五类轮廓并补盖、绳结、耳柄；篮子由交织网格与深色内织面构成，搭配麻布和食材；双灶用真实布尔凹洞与内嵌薪柴 | 不扩大主要家具或占据既有路线；新增背景竹梯单独给薄碰撞盒 |

材料按三个尺度分工：宽岩面、碎边、树皮外轮廓用网格；颗粒、细裂纹、织物组织用可导出的切线法线；矿物斑、釉斑与灰缝用颜色和粗糙度。法线必须先按真实纹理尺度求高度梯度、归一化方向，再编码为 Non-Color RGB，不能把任意噪声当作法线图片。墙面颜色/法线/粗糙度为 1024，地板各 512；树皮颜色/法线 1024，其余家具贴图 512。

窗户要有厚石揭口与木框。背景独立命名 `FrogWindowBackground`，与实体窗格分开合批；父场景可只关闭背景投影，保留窗格投影。窗内局部天空与远树贴图只提供窗外深度，不能通过关闭房墙去看见整个外部场景。`home-layout.json` 的 `windows` 导出绝对坐标、内法线、宽高，灯光据此对准真实窗口。是否产生预期软阴影仍需引擎验证。

控制网页体积时，先保留原生 `.blend` 中的 PNG 贴图，再把运行 GLB 的不透明 Base Color 转为 JPEG；法线和粗糙度仍保留无损 PNG。这一步用线性 0.25 对应的 sRGB 0.537099 灰块验证，JPEG 解码仍为 137/255，未再次改变编码。它只检查此保存流程的颜色空间；JPEG 有损误差与引擎纹理压缩仍须在最终实机画面检查，不能据此宣称像素完全一致。


## 烘焙后暴露的窗木环反面

LightmapGI 审查中，蛙家的三个圆窗木环变黑。独立读取冻结 `home-enclosure.glb` 的真实三角后确认：木环参数网格绕序向内，每环 1280 个三角，三角法向与管体外向的点积约 -0.994，合计 3840 个反面。此前双面显示与直接照明没有充分暴露这一问题，不能据此推断法线正确。

已修正 `tools/build-frog-home.py` 中仅木环的面绕序，避免以后重建再次内翻。合并资产中的木环位于 `HomeDetails_05`，与门横木、窗竖格共享 `Home dark oak joinery` 材质；其余构件不可整体翻面。运行副本按木环空间形状筛选三角，反转绕序、法线及切线手性，保留 UV/UV2，再由 LightmapGI 流程重烘。

此次只更新生成脚本，没有重新生成或覆盖冻结的原生 `.blend` 和原导出 GLB；它们仍是本轮原档，不能称为已同步修正的源模型。独立运行修正版与重烘验收由运行流程记录；原 Blender 证据图及其摘要也不替代新烘焙证据。


同次烘焙还暴露了木环外侧的石窗楣黑圈。独立读取原 GLB 确认 `HomeDetails_07` 只含三个石揭口，每窗 256 个三角、共 768 个，面法向与窗内向法线点积全部为负（约 -0.825 至 -0.461）。角度方向再接向内层的原绕序实际朝向墙外。生成脚本已仅反转 `Home thick stone window reveal` 的面；运行流程可单独修这一网格并重烘，不翻转其他岩墙。此次仍未覆盖原 `.blend` 或原 GLB，原档与独立运行修正版的状态按上段区分。
