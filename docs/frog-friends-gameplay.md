# 旅行蛙：朋友日常

**状态：产品讨论稿，2026-09-13。以下新机制尚未实现，不代表当前网页功能。**

让朋友记得你做过的事，并在再次见面时回应。第一版围绕熊猫完成串门、做饭、送礼、出游；不把安静的小世界变成每日任务表。

## 第一次一起生活：6–10分钟

熊猫请你喝茶 → 邀请它来蛙家 → 一起做笋饭团 → 给它装一份 → 去营地野餐 → 留下一张双人回忆。每一步都能单独结束，下次继续；6–10分钟是完整体验的设计目标，不是限时要求。

| 环节 | 玩家操作 | 朋友的回应与小趣味 |
| --- | --- | --- |
| 串门 | 靠近熊猫，选择“坐坐 / 来我家 / 一起走走” | 转身招手，留出座位。第二次见面会提起上次的饭团或照片。 |
| 做饭 | 在灶台选食材，依次放入、拌匀、出锅 | 熊猫坐在桌旁看向冒气的锅。饭团可以歪一点，它会先拿最歪的那个；不判失败。 |
| 送礼 | 从行囊选饭团、茶罐或旅途小石头，确认送出 | 食物会一起分享；纪念物摆进它家固定位置。下次来仍看得到，不只弹一句感谢。 |
| 出游 | 选择去营地，沿小径同行，到达后摆饭、合影 | 你停下它也停。木桥边一起看水，野餐时互换一口吃的；合影保存在回忆里。 |

关系由共同经历推进：第一次一起做饭、送礼、野餐分别开启新的回应。重复串门不刷好感；也不展示一根需要填满的关系进度条。回访时，熊猫记得具体的东西，例如“那块小石头，我放窗边了”。

## 第一版做到哪里

先做 **1位熊猫朋友、2道食谱（笋饭团、清茶）、3种礼物、1条营地路线、约8段情境回应**。复用蛙家、熊猫家、灶台、茶具、营地和相册。基础食材可免费补充，采集仅增加口味；原有三叶草不成为朋友玩法的强制门票。

做饭是三次轻操作，没有精准节奏、烧焦惩罚或等待计时。熊猫可以主动提议，但玩家随时选“下次”。没有连续签到、离线掉好感、过期邀请、每日清单或限时独占奖励。

当前已有熊猫屋内短路线、招呼/坐下动作、喝茶和单人便当野餐。**做饭、礼物展示、朋友记忆及户外同行需要新增。** 户外先沿已验收小径建立一条同行路线，遇阻停下并重新寻路，进出房间同步伙伴；不靠穿家具或常态瞬移完成跟随。第一版不同时扩建三个朋友的住宅。

## 手机、存档与中断

沿用摇杆和情境互动按钮，靠近时显示“聊天 / 做饭 / 送礼”；一次最多三项选择，触摸目标至少44px。弹窗打开时暂停移动与视角输入。返回门户、切换语言后仍可继续；门户以后可显示一句“继续和熊猫的野餐”，不另开任务大厅。

新增存档版本，保留现有三叶草、相册与进度，并记录：

- **朋友**：共同经历、送过的礼物、待回应邀请；不把每次进门增加的 `panda_visits` 当作关系。
- **物品与摆放**：食材、料理实例、纪念物，以及家中固定槽位上的物件。
- **活动**：当前伙伴、活动阶段、最近安全恢复点；**回忆**：事件ID、地点、食谱/礼物ID、照片ID。

出锅、送出、野餐完成后立即保存。唯一事件ID防止重复扣物品或重复奖励。中途关网页时保存已完成阶段；回来从安全位置继续，材料不作废。浏览器本地存档为首版基础，不假设已实现跨设备同步。验收要实际覆盖刷新、离开门户再返回、送礼后中断和重复恢复。

行为由确定的状态机和情境文案驱动，不依赖付费Agent、API Key或持续联网。

## 后续朋友要有不同相处方式

**胖橘**喜欢暖和的地方，做饭时围着香味转，出游更愿意短途晒太阳。它可以对你选的野餐位置作出不同反应，不新增一套喂养倒计时。

**松鼠**喜欢采集和收纳，会带你找一处小藏物点，送礼后认真摆好；同行时先去前面看看，再回来等你。差异落在动作、喜欢的活动和回访痕迹上，不只是换模型、换名字。两者均是后续提案，不计入首版完成范围。

## 共创一张小餐桌

首版之后可加入“送你一桌茶”：玩家在三个固定槽位选择茶具、点心、花瓶，导出带分享码的茶席卡。别人导入、预览并确认后，应用到自己家的客用茶席；服务不可用时也能本地导入分享码。

分享码仅含格式版本、白名单物件ID和槽位，不执行代码、不改建筑或公共地图。导入前保存旧布局，可撤销；同一槽位冲突时让玩家选保留哪一套，不自动覆盖或叠放。重复导入按方案ID去重。精选方案以后可以成为主世界的**可选模板**，须经过单独审核，不由访客直接合并到所有人的世界。

本次讨论只形成设计范围。下一步应先完成“熊猫来做客→做饭→留下回忆”的可玩片段，再接礼物展示和一条同行路线，以实际互动和中断恢复验收，不能用几段提示文案替代玩法完成。
