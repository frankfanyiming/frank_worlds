# 熊猫朋友日常：实现与验证

状态：已接入本地真实 Godot 场景；网页发布以本轮 release.json 为准。胖橘、松鼠和共创茶席仍是后续提案。

## 玩家可以做什么

去熊猫家靠近熊猫，分享一杯茶、邀请它来做客。它以已有 Tripo 身体与 Walk / Idle / Sit / Turn 动作跟随，经过同一扇门进入蛙家。在窗边双口灶台做笋饭团或清茶：放入、拌匀/注水、包好/分杯，各三次操作，没有计时、失败或付费食材。每次完成得到两份料理。

将一份料理、茶罐或旅途小石头送给熊猫。料理摆在茶桌，茶罐留在柜子，小石头留在窗侧；回访仍可见，问候会提及礼物。同行到橙色帐篷旁，摆开剩余料理，拍一张两个人都在场的真实画面，照片同时进入原旅行相册和朋友记忆。一次面板最多三个选项；五语言由同一个语义动作接口提供。

伙伴走得慢，有真实脚步；停下时它会靠近再等候。室内用实际家具碰撞采样的地面图寻路，户外同时记录玩家经过的路径点。脚步速率由碰撞后的真实位移决定，堵住时重寻路；不会为了追上玩家而常态瞬移。两位友方角色互不阻塞，墙和家具仍阻塞两者。室内外是独立引擎坐标空间，过门时双方使用相同门口转场，不声称这一步是连续几何穿门。

## 文件与接口

- `worlds/frog/source/friends/friend_state.gd`：本地数据版本与交易事件表。
- `friend_life.gd`：交互、礼物实物、照片、阶段与恢复。
- `friend_follow.gd`：静态碰撞采样地面图、户外路径痕迹、实际 CharacterBody 行走。
- `save_recovery.gd`：Web同步JSON镜像、新旧版本比较、未落盘合影恢复。
- `text.json`：简中、繁中、日语、韩语、英语同键文案。
- `world.gd`：独立节点生命周期、附近互动、门口转场、行囊入口。

网页桥读取 `get_friend_ui_state(locale)` 与 `get_friend_hud_state(locale)`，选择调用 `friend_ui_action(id)`。朋友状态打开时隐藏其他面板并锁移动；合影期间 `friend_life.busy_photo` 为真，应保持输入锁。原行囊仍可查看原便当；新朋友料理不花三叶草。

## 本地保存

原 `woodland-save.json` 加 `friend_life` 字段，保留三叶草、已备便当、采收时间、原相片及访问次数。访问次数不作为关系值。每次出锅、送礼、摆野餐、生成回忆立即保存；站稳后每五秒保存当前两人位置，进出屋保存房间与位置。未完成料理记录配方与步骤，恢复无需重新取材料。

每份料理有实例 ID，交易以唯一事件 ID 记录，重复出锅/送礼/照片回调不能重复增减。界面进一步验证当前可选动作，阻止旧按钮再次发送而消耗下一份料理。礼物只放预定义槽位，不加载任意代码或网络资源。照片失败时仍保留野餐阶段，允许重拍。

Web 的 `user://` 经下一帧异步同步到 IndexedDB；文件关闭并不意味着浏览器已经提交。现在每次保存先写稳定键 `xlands:frog:state:v1` 的小型 localStorage JSON 镜像，再写原文件。加载以保存序号、时间选择较新版本，旧镜像不会覆盖较新 IDB；localStorage 不可用或超额时仍走原 userfs 保存。图片字节仍只存 IDB：未落盘的朋友合影回到已摆好野餐的可重拍阶段，不重复扣料理；普通旧照片记录保留，相册仅统计和显示实际存在的图片。恢复房间后立即重存最终坐标，避免再次快速刷新回到门口。

仅使用浏览器本地存档，未实现跨设备同步；不依赖付费 Agent 或 API Key。

## 已完成验证与范围

`tools/test-frog-friends-state.gd` 的 22 项验证：事件幂等、料理份数、礼物扣减、固定摆放槽、野餐消耗、记忆去重、空物品保护及五语言键覆盖。

`tools/test-frog-friends-runtime.gd` 覆盖原存档迁移、真实入口行走、室内外碰撞层、6段灶台路线、3步料理防重复操作、送礼后回访实物、第二配方、双人照片及销毁重建世界后的保存恢复，以及连续快速重载坐标和缺失旧照片的相册空态，共34项。营地照片与第二次配方使用显式场景测试位置，不冒充完整地图行走；全路线另由 `test-frog-friends-route.gd` 验证。

整条熊猫家→营地→东桥头→过桥→蛙家路线的四段真走均通过，熊猫真实累计位移67.29米。

原始 JSON 与实际渲染图在 `docs/evidence/frog-friends/`。这些图片是实际引擎运行，不是生成概念图。网页新 UI 的截图、移动端触摸和最终在线验证由统一界面/发布验收补充。
