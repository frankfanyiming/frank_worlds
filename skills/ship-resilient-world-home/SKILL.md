# 发布可恢复的小世界首页

保持项目现有托管架构，除非用户要求迁移。首页、世界资源、社区 API、数据库和浏览器存档分别确认位置，不因有服务器截图就假设已有部署权限。

## 首页先可读

返回的 HTML 直接包含品牌、世界入口、作者联系方式和分享说明。首页不静态导入 3D 引擎，封面独立压缩并设定尺寸。社交入口使用普通外链，不加载社交时间线脚本。

交互脚本未完成时保留基本页面。挂载超时、脚本错误和 React 渲染失败应显示可用的静态引导；故障面板自带 CSS、链接和重试，不依赖已经崩溃的模块。不能承诺整个浏览器进程崩溃后页面仍能运行。

## 外部服务故障

检查实际 HTTP 状态、Content-Type 和应用 JSON。403 HTML 保护页与应用返回的 JSON 权限错误分开处理；无 CORS 头不自动证明应用 allowlist 错误。不要绕过访问保护。

网络失败保留输入，明确“未保存”，提供用户主动点击的联系入口。复制留言只复制正文，不包含非公开邮箱或自动发给第三方。不要把失败后的状态仍写成“正在连接”。

公开账号先验证链接：self 路径通常指向当前访问者，而不是作者。拿不到准确主页时展示账号与复制入口，不猜测 slug。

## 发布证据

按项目流程构建与检查，发布用户授权的范围。保留无关工作；大文件分批传输时，最终比较候选树与上传树，处理重命名的新增和删除两端。

记录源码提交、发布提交、工作流和 release 清单。通过公开 URL 重新下载入口及变更文件核对长度/摘要，保留旧哈希延迟模块以服务仍打开的页面。git push 返回成功不等于网页已更新。

报告构建/HTTP/浏览器/真机各自做过什么。没有真机测量时不能宣称手机流畅；没有后端 JSON 时不能宣称留言恢复。将本轮的新故障、证据、有效修正及适用范围写回经验文档。
