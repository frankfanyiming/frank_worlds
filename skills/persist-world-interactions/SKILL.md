# 让朋友日常与存档连续

先将玩法写成玩家可见的状态链，例如串门 → 共同料理 → 送礼 → 邀请同行 → 野餐合影。每步明确前置条件、消耗、获得、退出和恢复位置。优先保留用户已有进度，不用重置存档修复问题。

## 同伴行为

跟随使用角色实际速度、距离和可通行路径更新。旧足迹、目标更新过慢、导航范围太小都会导致伙伴停住。检查整个人体宽度和桥头标高，不能缩小碰撞体掩盖断路。

验收时连续走、跑、转弯、过桥和离开原范围，不要每走几步等待伙伴来掩盖落后。记录距离与实际运动；对话和动画不应无意阻塞跟随。

## 存档边界

定义版本化、可序列化的小状态：料理步骤、食物与礼物、好友关系、同行目标、场景与位置、照片索引。读取旧版本时规范化缺失值，保留未知或尚未迁移的数据。

引擎文件关闭不等于浏览器 IndexedDB 已持久化。通过即时刷新验证真实落盘边界。若需要小状态同步检查点，可在合法配额内使用 localStorage 镜像；大照片留在 IndexedDB，避免把图像塞进小状态。

镜像与异步存档比较版本或更新时间，不能让较旧镜像覆盖新存档。恢复后的自动保存也不能用临时出生点覆盖恢复位置。

## 验证

在多步料理中间重建场景和刷新；连续刷新；模拟存储配额不足；检查旧照片仍存在、新照片只保存一次。明确测试中直接设置的状态或坐标，不将其写成整段正常游玩证据。

本地存档只属于该浏览器与站点来源。换域名、换设备和共享留言数据库是不同问题，跨设备同步需要单独的服务设计和用户授权。
